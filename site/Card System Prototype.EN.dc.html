CD Build notes — what's realistic, from the build side

Piece A — the sheet

  • Format: CSV is the easiest and most reliable to parse. Excel (.xlsx) needs an unzip+XML step; a Google Sheet works great via File → Publish to web → CSV, which we can re-fetch on load. Recommend authoring in Google Sheets, ingesting the published CSV.
  • Schema: the current columns are good. Keep id · order · type · eyebrow · title · body · image · bg · link · status, add date for true newest-first.
  • Updates: re-drop the whole sheet, everything regenerates. The id column keeps identity + order stable across updates — change a cell, the same card updates in place.
  • Images: reference a committed repo file or a full URL — both work. Don't rely on drag-drop into the page (those vanish on edit); commit the file or host it so the reference stays baked in.
  • Background: a named token (teal, magenta, amber…) keeps taxonomy consistent; a raw hex is accepted as an override.
  • Ceiling: client-side is comfortable into the low thousands of rows. Past a few thousand, or once you need auth / relations / real search, that's the cue to move to the Constellation backend.

Piece B — the "More" page
